# ADR-0010: Подсветка синтаксиса в блоках кода

## Status

Утвержден

## Date

2026-09-22

## Context

Блок кода с меткой языка (```` ```csharp ````) сейчас показывается одним цветом
текста. Для README, заметок и документации с примерами это главный недостаток
чтения кода: комментарии, строки и ключевые слова не отличаются от остального
текста.

Ограничения те же, что у диаграмм (ADR-0005): viewer-first, быстрый путь
«открыть файл → увидеть документ» не утяжеляется, всё локально, без сети и
внешних процессов, сборка — Native AOT на Windows, macOS и Linux.

Движок выбирался из семи вариантов. Два прошли в пробу — tree-sitter и
TextMateSharp: Native AOT, osx-arm64, одни и те же блоки C#, bash, Python, JSON,
TypeScript, YAML.

| | tree-sitter (TreeSitter.DotNet 1.3.0) | TextMateSharp 2.0.4 |
|---|---|---|
| AOT | собирается с предупреждениями IL2104/IL3053, работает | без предупреждений |
| Прибавка к размеру | весь пакет +63 МБ, 15 популярных языков +19 МБ | 52 языка +8,2 МБ; со сжатыми грамматиками около +2–3 МБ |
| Нативные библиотеки | ядро + библиотека на каждый язык × платформа | одна `libonigwrap` около 0,5 МБ |
| Языки | 25, нет yaml, markdown, sql, xml, toml, dockerfile | 52, включая yaml, sql, xml, dockerfile, powershell |
| Правила цветов | в пакете нет, `highlights.scm` собирать самим | не нужны |
| Первая подсветка языка (медиана 7 запусков) | 0,3–23 мс | 0,3–80 мс (bash и TypeScript около 80 мс) |
| Повторная подсветка блока | 0,02–0,14 мс | 0,08–1,8 мс |
| Качество | лучше в bash | лучше в интерполяции C# и вызовах методов в TS |

Для масштаба: приложение до изменения — около 77 МБ без отладочных файлов.

Самое дорогое у TextMateSharp — первая загрузка грамматики (до 80 мс). Если
подсвечивать внутри `RenderMarkdownDocumentUseCase`, как диаграммы по ADR-0005
§5, эта цена ляжет на UI-поток: `ShellViewModel.ApplyLoadedDocument` рендерит
документ синхронно.

## Decision

Подсветка — на TextMateSharp со сжатыми грамматиками, отдельным шагом **после**
показа документа.

### 1. Движок — TextMateSharp

- Пакеты `TextMateSharp` (разбор, `Registry`, грамматики TextMate) и
  `TextMateSharp.Grammars` (грамматики VS Code). Сборка `TextMateSharp.Grammars`
  в приложение не попадает: из неё при сборке берутся только файлы грамматик
  (§6).
- Регулярные выражения — Oniguruma через нативную `libonigwrap` (пакет
  `Onigwrap`, по библиотеке на платформу, около 0,5 МБ).
- Тема TextMate не используется: `Registry` получает пустую тему, цвета
  выбираются по скоупам (§3) и берутся из `Themes/Colors.axaml`.

### 2. Язык блока

- Язык — первое слово метки после ```` ``` ````, без учёта регистра.
- Метка сравнивается с идентификатором языка, его синонимами (`aliases`) и
  расширениями файлов (`extensions` без точки) из `package.json` грамматик:
  `sh`, `yml`, `js`, `py`, `cs`, `ps1` работают без отдельной таблицы. Сверх
  них — только `shell`: частая метка на GitHub, которой нет среди синонимов.
- Автоопределения языка нет: блок без метки или с неизвестной меткой
  показывается как раньше.

### 3. Виды токенов

Блок кода получает список токенов `(Start, Length, Kind)` поверх неизменного
текста. Виды (`MarkdownCodeTokenKind`, `Domain`):

| Вид | Скоупы TextMate |
|---|---|
| `Comment` | `comment.*` |
| `Keyword` | `keyword.*` (операторы — только словами: `new`, `typeof`, `as`), `storage.type`, `storage.modifier`, `variable.language`, `constant.language` (`null`, `true`, `false`, `None` — как в Rider) |
| `StringLiteral` | `string.*`, `constant.character.escape`, `storage.type.string` (префикс `f"…"` Python) |
| `Constant` | `constant.numeric`, `support.constant`, `entity.other.attribute-name` |
| `Type` | `entity.name.type`, `entity.name.class`, `entity.other.inherited-class`, `support.type`, `support.class`, `entity.name.tag` (ключи JSON и YAML, теги XML и HTML) |
| `Function` | `entity.name.function`, `support.function` |
| `Member` | `variable.other.object.property`, `variable.other.property`, `support.variable.property`, `entity.name.variable.field`, `entity.name.variable.property`, `meta.attribute` — свойства и поля |
| `Inserted` / `Deleted` | `markup.inserted` / `markup.deleted` (строки `diff`): строка получает фон во всю ширину листа (`MmSyntax{Inserted,Deleted}BackgroundBrush`), цветом `MmSyntax{Inserted,Deleted}Brush` — только знак `+`/`-`, текст строки — цветом текста |

Правила разбора:

- Цвет токена — по самому внутреннему скоупу, у которого есть вид.
  Знаки начала и конца строк и комментариев (`punctuation.definition.*`) своего
  вида не имеют и берут цвет родителя.
- Подстановки внутри строк не красятся как строка: `meta.embedded`,
  `meta.interpolation`, `meta.template.expression` и `variable.*` на пути от
  токена к строке прерывают поиск (`{name}` в C#, `${name}` в TS, `$CI` в bash).
- Всё прочее — пунктуация, операторы, имена переменных — цветом текста.

- Объект перед точкой (`dbContext`, `Gender`, `RussianConverter`) остаётся
  цветом текста: поле, локальная переменная или тип — по тексту не различить.
- Shell (пакет `shellscript`): грамматика красит только встроенные команды,
  а `dotnet`, `git`, `npm` оставляет текстом — блок `dotnet --version`
  выглядел неподсвеченным. Поэтому поверх грамматики первое слово в позиции
  команды — начало строки, после `|`, `&&`, `;`, `(`, `$(`, обратной кавычки
  и `then`/`do`/`else`/`if`/`while`/`until` — получает вид `Function`, как на
  GitHub (`ShellCommandNames`). Присваивания `FOO=1` перед командой и промпт
  `$ ` пропускаются, после `sudo`/`env`/`nohup`/`exec`/`xargs` ждётся ещё одна
  команда, строка после `\` — продолжение аргументов. Аргументы — цветом
  текста. Подстановку `$(…)` и `` `…` `` грамматика размечает строкой — она
  рисуется цветом текста, как код.

Палитра — цвета Rider (выбор пользователя из вариантов на холсте «Стиль
документа MarkMello», страница «Подсветка кода»): Rider Light и Rider Dark с
тем же тоном oklch; светлота сдвинута там, где контраст с фоном блока ниже,
чем у `MmTextSoftBrush`, — в светлой теме строки, методы, свойства и
комментарии поэтому темнее, чем в Rider. Rider различает то, чего TextMate не
видит: структуры и enum темнее классов, члены enum жирные, поля отличаются от
локальных переменных, — здесь этого нет. Значения — в `Themes/Colors.axaml`,
ключи `MmSyntax*Brush`, по правилу ADR-0009 §9.

### 4. Докраска после показа

- `RenderMarkdownDocumentUseCase` подсветку не делает. Документ показывается
  сразу, без цветов.
- `HighlightCodeBlocksUseCase` (`Application`) проходит блоки, включая цитаты,
  алерты, списки, сноски и определения, и возвращает документ с токенами.
  `ShellViewModel` запускает его вне UI-потока, когда view нарисовала
  документ (не раньше — иначе разбор отнимает время у первого показа), и
  применяет результат, только если на экране всё ещё тот же документ; при
  смене документа или вкладки незавершённая докраска отменяется. Вкладка
  хранит документ с цветами, а повторно открытый файл берёт их из кэша сразу.
- View пересобирает только блоки, у которых появились токены
  (`MarkdownBlockStructuralComparer` учитывает токены); прокрутка и выделение
  сохраняются.
- Превью режима правки подсвечивается внутри уже фонового
  `DebouncedEditorPreviewScheduler`. Кэш по паре «язык + текст» общий, поэтому
  неизменившиеся блоки получают цвета сразу и не мигают без них на каждой
  правке. Синхронный рендер превью на UI-потоке берёт токены только из кэша.
- Документ без блоков кода с меткой языка не запускает ни фоновую задачу, ни
  TextMateSharp. Реестр грамматик создаётся при первом блоке с известным
  языком, грамматика языка — при первом блоке этого языка.

### 5. Пороги и таймаут

- Блок длиннее 50 000 символов или 2 000 строк не подсвечивается.
- На блок — не больше 500 мс разбора. Загрузка грамматики и компиляция её
  правил (прогрев пустой строкой) в бюджет не входят: иначе первый блок
  тяжёлого языка (C++) упирался бы в таймаут из-за загрузки. Остаток бюджета
  передаётся TextMateSharp лимитом на каждую строку, поэтому и одна «тяжёлая»
  строка не затянет разбор. Упёрся — блок сейчас без цветов, но ответ не
  запоминается: таймаут зависит от нагрузки машины, следующая докраска
  попробует снова.
- Кэш — не больше 512 блоков и 1 000 000 символов кода (правка большого блока
  в превью кладёт в кэш каждую его версию), вытесняется самый давний.
- Докраска превью отменяется, когда запланирован новый рендер: устаревший
  разбор не держит общий движок.
- Пересборка после докраски не повторяет действий первого показа: фокус,
  прокрутка к совпадению поиска и миникарта остаются как были.
- Ошибка движка, неизвестная метка, порог и таймаут — блок выглядит как
  раньше, без сообщения пользователю и без записи в лог на каждый блок.

### 6. Упаковка

- Из `TextMateSharp.Grammars` при сборке берутся только `package.json` и
  `syntaxes/*.json` каждой грамматики и складываются в один zip, встроенный
  ресурсом в `MarkMello.Infrastructure`. Сниппеты, темы, настройки языков и
  переводы не берутся.
- Грамматика читается из zip по требованию. Для блока загружаются только
  грамматики пакета его языка: грамматика bash подключает в heredoc
  markdown, html, ruby и python, markdown — ещё десятки языков, и цепочка
  целиком стоила 56 МБ памяти и 150 мс ради одного блока bash (после
  ограничения — 0,8 МБ и 30 мс). Чужой язык внутри блока (скрипт в heredoc,
  fence внутри markdown, `<script>` в html) остаётся без цветов. Самая
  тяжёлая из оставшихся — грамматика C++: около 23 МБ.
- `libonigwrap` лежит рядом с исполняемым файлом во всех пакетах: `.app` на
  macOS (подписывается вместе с остальными нативными библиотеками),
  установщик Windows, AppImage Linux.

Прибавка к AOT-сборке osx-arm64 — в разделе «Размер».

### 7. Слои

- `Domain`: `MarkdownCodeTokenKind`, `MarkdownCodeToken`, `MarkdownCodeBlock.Tokens`
  (`null` — блок не подсвечен).
- `Application`: `ICodeHighlighter` (язык + код → токены или «не подсвечено»),
  `HighlightCodeBlocksUseCase` (обход блоков, пороги, кэш, отмена).
- `Infrastructure/Highlighting`: реализация на TextMateSharp, zip грамматик.
- `Presentation`: цвет токена — кисть из ресурсов по виду; текст, выделение,
  копирование и поиск по-прежнему работают с исходным текстом блока.

### 8. Вне рамок

Подсветка inline-кода, миникарты, HTML-превью и редактора исходника;
автоопределение языка; настройка «вкл/выкл» и выбор темы подсветки.

## Размер

Замер — AOT-сборка osx-arm64, `dotnet publish -c Release -r osx-arm64
-p:PublishAot=true`, без `.dSYM`:

| | До | После | Прибавка |
|---|---|---|---|
| `MarkMello` | 57 643 912 | 58 999 912 | +1 356 000 (код TextMateSharp и zip грамматик 0,86 МБ) |
| `libonigwrap.dylib` | — | 531 424 | +531 424 |
| Всё без `.pdb` и `.dSYM` | 77 318 056 (73,7 МиБ) | 79 205 480 (75,5 МиБ) | +1 887 424 (+1,8 МиБ) |

Цель была около +3 МБ.

Старт (`tools/measure-startup.py`, AOT, медиана 10 прогонов, порядок
«до · после · после · до», 2026-09-22):

| Документ | ReadableDocument до | после | Пик памяти до | после |
|---|---|---|---|---|
| `samples/showcase.md` (bash, C#, diff, JSON, YAML) | 324,1 / 320,7 мс | 319,5 / 321,9 мс | 248 МБ | 261 МБ |
| он же без меток языка | 353,9 / 361,3 мс | 353,4 / 357,9 мс | 247,4 МБ | 247,4–247,6 МБ |

Строки сняты разными сериями: сравнивать только «до» и «после» внутри строки.
Документ без знакомого языка не загружает ни TextMateSharp, ни
`libonigwrap`; пик памяти с подсветкой пяти языков — +13 МБ.

## Rejected alternatives

- **tree-sitter (TreeSitter.DotNet).** Быстрее на первой подсветке, но
  предупреждения AOT, +19 МБ даже на 15 языков, по нативной библиотеке на язык
  и платформу, нет yaml, sql, xml, toml, dockerfile, правила цветов
  (`highlights.scm`) пришлось бы собирать и поддерживать самим.
- **ColorCode.Core.** Около 20 языков на регулярных выражениях, нет yaml, bash,
  TypeScript; качество заметно хуже TextMate.
- **JS-движок (Jint + highlight.js).** Интерпретатор JavaScript в процессе ради
  раскраски: медленный первый запуск, тяжёлый рантайм, вопросы AOT.
- **PrismSharp.** Порт Prism на .NET с небольшим набором языков и без
  активной поддержки.
- **Свой токенизатор.** Для 5–10 языков выглядит просто, но каждый язык —
  своя поддержка и свои ошибки; TextMate даёт 52 языка готовыми.
- **AvaloniaEdit xshd.** Формат подсветки редактора AvaloniaEdit: подключает
  редактор к viewer mode, мало языков, свой формат правил.

## Consequences

- Прибавка к размеру приложения (раздел «Размер») и одна нативная библиотека на
  платформу.
- Первый блок нового языка получает цвета с задержкой до ~80 мс после показа
  документа.
- Новая зависимость в `Infrastructure` — `TextMateSharp` с `Onigwrap`.
