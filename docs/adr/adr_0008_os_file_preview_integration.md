# ADR-0008: Превью Markdown в Finder и Проводнике

## Status

Отложен (2026-09-22). Spike дал вердикт «macOS — делаем, Windows — до
spike», но сама работа (MM-9 – MM-12) перенесена в бэклог. Решения ниже —
предложение, к которому возвращаемся при возобновлении; тогда же
пересмотреть пункты, помеченные «проверить».

## Date

2026-09-22

## Context

В Finder по пробелу (Quick Look) и в панели просмотра Проводника (Alt+P) файл
`.md` показывается исходником. Хочется видеть документ таким, каким его
показывает MarkMello, не открывая приложение.

Превью показывает сама ОС, в своём процессе, через расширение приложения:

- macOS — Quick Look extension (`.appex`) внутри `MarkMello.app`. Расширение
  обязано быть подписанным и работать в песочнице. `MarkMello.app` сейчас не
  подписан Developer ID и не нотаризован (ADR-0004 откладывает это, шаг 5).
- Windows — Preview Handler: COM-сервер, который Проводник загружает в
  `prevhost.exe`.

Avalonia в этих процессах недоступна: ни у расширения Quick Look, ни у
Preview Handler нет места для рендера на Skia с нашим UI-стеком без запуска
приложения. Поэтому превью — HTML, который ОС показывает своим веб-движком
(WebKit на macOS, WebView2 на Windows).

Риски, которые проверял spike (MM-9): заработает ли ad-hoc подпись для
скачанного DMG; загрузится ли NativeAOT-библиотека в песочнице; прочитает ли
расширение картинки рядом с документом; каким способом писать COM-сервер на
Windows и как не сломать чужой обработчик `.md`. Результаты —
`tests/quicklook-macos-spike.md` и `tests/preview-handler-windows-spike.md`.

## Decision

### 1. Платформы

- **macOS** — Quick Look extension, data-based preview
  (`QLPreviewProvider`, ответ — HTML через `QLPreviewReply`), macOS 12+.
  Тонкая обёртка на Swift, собирается `swiftc` из Command Line Tools.
- **Windows** — Preview Handler в панели просмотра Проводника, HTML через
  WebView2. Предварительно — тонкая обёртка на C++ (COM-сервер + WebView2
  C++ SDK); окончательно — по итогам spike на Win11.
- **Linux — вне рамок.** Причины:
  - у GNOME Sushi (просмотр по пробелу в Nautilus) нет API для сторонних
    рендеров: заменить можно только весь previewer через D-Bus-имя
    `org.gnome.NautilusPreviewer` — это хак против норм платформы и против
    ADR-0004 («не навязываться как обработчик по умолчанию»);
  - в Ubuntu Sushi по умолчанию не установлен;
  - AppImage (ADR-0004) не ставит системных интеграций — расширению негде
    жить;
  - в KDE Dolphin просмотра по пробелу нет.

### 2. Проект `MarkMello.Preview`

- Новый проект `src/MarkMello.Preview` — NativeAOT shared library и **свой
  composition root**. Ссылается на `Domain`, `Application`, `Infrastructure`.
  На него **не ссылаются** `Desktop` и `Presentation`: быстрый путь открытия
  документа не меняется, в процесс приложения библиотека не грузится.
- Наружу — C-интерфейс: `mm_render_html(path) → char*` (UTF-8, память
  библиотеки) и `mm_free(char*)`. Одна и та же библиотека под обе платформы;
  платформенные обёртки (Swift, C++) только вызывают её и отдают HTML ОС.
- Библиотека не использует Avalonia и не читает настройки MarkMello.

### 3. HTML из доменной модели

- HTML строится обходом `RenderedMarkdownDocument` — того же результата
  `RenderMarkdownDocumentUseCase`, что показывает приложение, — а не
  стандартным `HtmlRenderer` Markdig. Так превью видит те же расширения
  разметки, те же ограничения (`MarkdigMarkdownDocumentRenderer` сознательно
  берёт не все расширения Markdig) и тот же фолбэк в исходник.
- Диаграммы — через существующий `IDiagramRenderer` (Naiad) во встроенный
  SVG; ошибка или лимит — блок кода с исходником.
- Подсветка синтаксиса (ADR-0010) в первую версию не входит: +3 МиБ
  TextMateSharp и `libonigwrap` в каждую копию библиотеки. Можно добавить
  позже тем же `HighlightCodeBlocksUseCase`.

### 4. Оформление

- CSS-токены цветов и шрифтов **генерируются при сборке** из
  `Themes/Colors.axaml` (обе темы) и `Themes/Typography.axaml`. Руками цвета в
  CSS не пишутся.
- Пропорции заголовков, таблиц, отступов переносятся в CSS вручную по
  `Views/MarkdownDocumentView.cs`: **похоже, не пиксель в пиксель**.
- Шрифты — Source Serif 4, Inter, JetBrains Mono, встроены в HTML; их
  OFL-лицензии идут в дистрибутив.
- Тема — из системы (`prefers-color-scheme`), язык служебных строк — из
  языка системы (`ru*` — русский, иначе английский). Настройки MarkMello
  (тема, шрифт, ширина) в превью **не учитываются**: у расширения нет доступа
  к `settings.json` приложения, а чтение его из песочницы — лишний риск ради
  малого выигрыша.

### 5. Безопасность и лимиты

- Превью **не ходит в сеть**: картинки `http(s)` — alt-текстом, ссылки только
  выглядят ссылками, скриптов нет, CSP запрещает всё, кроме встроенных стилей,
  `data:`-картинок и шрифтов.
- Лимиты: размер файла (сверх — исходник в `<pre>` с пояснением), размер
  одной картинки и всех вместе, число диаграмм. Пороги подбираются замером в
  MM-10 и дописываются сюда.
- Ошибка чтения, пустой или отсутствующий файл, отказ в доступе — страница с
  пояснением, без падения процесса ОС.

### 6. Соседние файлы (картинки)

- **Windows**: относительные и абсолютные локальные картинки встраиваются как
  `data:` URI (нужен путь к файлу — `IInitializeWithFile`, см. §8).
- **macOS**: песочница разрешает чтение соседних файлов исключением
  `com.apple.security.temporary-exception.files.absolute-path.read-only`, и
  оно работает. Но в папках под TCC (`~/Downloads`, `~/Desktop`,
  `~/Documents`, iCloud Drive) чтение соседнего файла вызывает системный
  запрос «Приложение запрашивает доступ к папке…» — на нажатие пробела. Поэтому
  расширение **читает только сам документ**; картинки из файлов
  показываются alt-текстом. Исключение песочницы расширению не выдаётся.
  Пересмотреть, если найдётся способ читать соседей без запроса.

### 7. macOS: упаковка и подпись

- `MarkMelloQuickLook.appex` лежит в `MarkMello.app/Contents/PlugIns/`,
  NativeAOT-библиотека — в `Contents/Frameworks/` расширения. Entitlements
  расширения — только `com.apple.security.app-sandbox`.
- Бандл подписывается **целиком, изнутри наружу**: библиотеки → `.appex` с
  entitlements → `.app`. Сейчас бинари несут только подпись линкера, а бандл
  не запечатан; этот шаг добавляется в `packaging/macos` и в релизный
  workflow. С появлением Developer ID (ADR-0004, шаг 5) шаг меняет `-` на
  identity и добавляет hardened runtime.
- Ad-hoc подписи достаточно, но расширение регистрируется только **после
  первого запуска** MarkMello (пока приложение в карантине и не запускалось,
  система его не видит). Это пишется в README и в тексте релиза.
- Xcode в CI не нужен: раннерам `macos-26` хватает `swiftc`.

### 8. Windows: регистрация

- Только per-user, без прав администратора, в том же `HKA`, что и остальные
  ассоциации установщика (`packaging/windows/MarkMello.iss`).
- **Чужой обработчик `.md` не перетирается** (например, Markdown preview из
  PowerToys пишет в тот же ключ `.md\shellex\{8895b1c6-…}`). Предпочтительно —
  регистрация на ProgID `MarkMello.Markdown`: превью MarkMello действует, когда
  пользователь выбрал MarkMello приложением по умолчанию. Если spike покажет,
  что так Проводник обработчик не находит, — регистрация на `.md` только при
  пустом ключе, флажком в установщике; при удалении значение убирается, только
  если оно наше.
- Инициализация — `IInitializeWithFile`: без пути к файлу относительные
  картинки не разрешить. Цена — `.md` внутри zip без превью.
- Папка данных WebView2 — своя (`%LOCALAPPDATA%\MarkMello\…`): рядом с
  `prevhost.exe` писать нельзя.

### 9. Связь с ADR-0004

Превью — продолжение интеграции с Finder и Проводником из ADR-0004: всё
ставится штатным пакетом (DMG, установщик Inno Setup), ничего не навязывается
по умолчанию, обновляется вместе с приложением. Раздел ADR-0004 про подпись
macOS не меняется: превью работает и без Developer ID.

## Размер

Замер spike — NativeAOT, `osx-arm64`, без `.dSYM`:

| Состав библиотеки | Размер |
|---|---|
| рантайм + чтение файла (нижняя граница) | 1,2 МиБ |
| + Markdig и слои MarkMello, диаграммы исходником | 4,0 МиБ |
| + Naiad (Mermaid) | 25,0 МиБ |
| + TextMateSharp (не берём, §3) | 28,1 МиБ + `libonigwrap` 0,5 МиБ |

Шрифты — 13 TTF, 4,2 МиБ (в WOFF2 ориентировочно вдвое меньше).

Прибавка к DMG до сжатия: **около +30 МиБ** с Mermaid и шрифтами (около +8 МиБ,
если диаграммы в превью показывать исходником). Для сравнения: приложение —
около 75 МиБ. На Windows ожидается того же порядка (`win-x64` не замерялся).

Mermaid — почти весь вес: Naiad с Pidgin дают +22 МиБ. Решение «диаграммы в
превью — SVG» остаётся, но если размер установщика станет проблемой, первое,
что убирается, — Naiad из превью.

## Вердикт по платформам

- **macOS — делаем (MM-11).** Spike подтвердил: ad-hoc подписанное расширение
  регистрируется и работает в песочнице, NativeAOT-библиотека загружается
  (2 мс), рендер тестового документа — 3 мс, приложение с вложенным
  расширением и подписью всего бандла запускается как раньше. До начала MM-11
  вручную пройти: скачивание DMG браузером → «Всё равно открыть» → пробел в
  Finder; macOS 12; Intel.
- **Windows — откладываем до spike (MM-12).** Проверить было не на чем. План и
  чек-лист — `tests/preview-handler-windows-spike.md`. MM-12 начинается со
  spike; если WebView2 в `prevhost.exe` или регистрация без перетирания чужого
  обработчика не заработают — MM-12 уходит в Backlog.
- **Linux — не делаем** (§1).

## Rejected alternatives

- **Стандартный `HtmlRenderer` Markdig.** Быстрее написать, но превью
  разошлось бы с приложением: другие расширения разметки, другие фолбэки, нет
  диаграмм.
- **Рендер в картинку через Avalonia/Skia.** Нужен весь UI-стек в процессе ОС
  (десятки МиБ, Skia в песочнице), текст нельзя выделить и прокрутить.
- **Превью, которое запускает `MarkMello`.** Процесс приложения на каждое
  нажатие пробела — медленно, и ОС такие расширения не допускает.
- **Linux через подмену `org.gnome.NautilusPreviewer`.** См. §1.
- **C# NativeAOT COM-сервер на Windows целиком.** Официальная .NET-обёртка
  WebView2 не совместима с NativeAOT; ручное описание COM-интерфейсов WebView2
  дороже тонкой C++-обёртки. Окончательно — по spike.

## Consequences

- В CI появляется Swift (Command Line Tools на macOS-раннерах) и MSVC на
  Windows-раннерах; Xcode-проекта нет.
- DMG и установщик растут (раздел «Размер»).
- Упаковка macOS начинает подписывать бандл целиком — в том числе ради
  расширения; smoke-тест релиза должен проверять подписанный бандл.
- Два способа показать документ: приложение и HTML-превью. Изменения в
  доменной модели (новые виды блоков) нужно доводить и до HTML-рендера —
  тесты `MarkMello.Preview.Tests` должны ловить непокрытый тип блока.
- На macOS превью появляется только после первого запуска приложения.
