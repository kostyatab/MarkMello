# ADR-0011: Идентичность форка Softmark и источник релизов

## Status

Утвержден

## Date

2026-09-23

## Context

Репозиторий `kostyatab/MarkMello` — форк `dartdavros/MarkMello`. Форк выпускает
приложение сам, со своими релизами, и при этом продолжает забирать фичи из
оригинала обычным `git merge`.

Пока форк собирается под именем MarkMello, он неотличим от оригинала:

- локальная сборка без MSBuild-флагов ищет обновления в релизах `dartdavros`;
- у установщика Windows тот же `AppId` и ProgId, у бандла macOS тот же bundle id,
  каталог настроек тот же — поставить форк рядом с оригиналом нельзя, одна
  установка перетирает другую;
- в интерфейсе ссылки на сайт и телеграм оригинала.

Апдейтер выбирает ассет релиза точным совпадением имени
(`GitHubReleaseUpdateService`). Переименовать артефакты после первого релиза —
значит порвать автообновление у всех, кому сборка уже роздана. В форке релизов
пока нет, поэтому решение принимается сейчас.

## Decision

### Имя

Приложение называется **Softmark**. Вордмарк — «Soft» + акцентный «mark», одним
словом, Inter SemiBold. На стартовом экране и в окне «О программе» знак —
сам вордмарк, без картинки; буква «S» на терракотовой плитке остаётся только иконкой
приложения. Единственный источник имени в коде — `AppProductInfo.Name`; строки
интерфейса подставляют его, а не пишут литералом.

### «О программе» и «Настройки»

Сведения о программе — только о форке. Нижняя строка карточки «Настройки»:
имя, версия, лицензия и одна ссылка — GitHub `kostyatab/Softmark`. Окно
«О программе» показывает то же самое плюс строку атрибуции оригинала (ниже).
Автор оригинала, сайт `markmello.ru` и телеграм оригинала из интерфейса убраны:
благодарность оригиналу — строка атрибуции, а не его контакты.

### Что переименовывается, а что нет

Переименовывается только витрина — то, что видит пользователь: имя в интерфейсе
и заголовке окна, имена артефактов и исполняемого файла, идентификаторы установки,
метаданные сборки.

**Не переименовываются** namespace `MarkMello.*`, имена проектов, `MarkMello.sln`,
пути `avares://MarkMello.Presentation/...` и внутренние MSBuild-свойства
(`MarkMelloReleaseOwner`, `MarkMelloReleaseRepo` и подобные). Пользователь их не
видит, а их переименование превратило бы каждый мерж апстрима в сотни конфликтов.
Так конфликты остаются только в файлах, которые правят обе стороны (локализация,
`.iss`, воркфлоу, `AppProductInfo`, `Directory.Build.props`, таблица ассетов
апдейтера), и разрешаются подстановкой своего имени.

### Источник релизов

Источник релизов по умолчанию — `kostyatab/Softmark`. Сборка без флагов ищет
обновления там; воркфлоу, как и раньше, передаёт координаты текущего репозитория.

### Идентичность установки

Softmark ставится рядом с MarkMello и ничего с ним не делит:

| Что                      | Значение                                   |
|:-------------------------|:-------------------------------------------|
| Windows `AppId`          | `{763DFBA8-3EE1-4796-BDE3-512381BF602A}`   |
| Windows ProgId           | `Softmark.Markdown`                        |
| macOS bundle id          | `com.softmark.app`                         |
| каталог настроек         | `Softmark`                                 |
| каталог загрузок         | `Downloads/Softmark`                       |
| исполняемый файл         | `Softmark` (`Softmark.exe`)                |
| Linux desktop entry      | `softmark.desktop`, иконка `softmark`      |

Настройки оригинала не переносятся: Softmark начинает с чистого листа.

### Релизная матрица

Заменяет раздел «Release Matrix» ADR-0004:

- `Softmark-setup-win-x64.exe`
- `Softmark-setup-win-arm64.exe`
- `Softmark-macos-arm64.dmg`
- `Softmark-macos-x64.dmg`
- `Softmark-linux-x86_64.AppImage`

Имена в таблице ассетов апдейтера совпадают с тем, что выкладывает воркфлоу, один
в один.

### Атрибуция

Softmark распространяется по GPLv3, как и оригинал. В окне «О программе» есть одна
строка атрибуции: «Fork of MarkMello © 2026 MarkMello contributors» /
«Форк MarkMello © 2026 MarkMello contributors». Это единственная видимая строка
со словом «MarkMello». В `Directory.Build.props` копирайт оригинала сохраняется
рядом со своим.

## Consequences

### Positive

- Форк выпускается и обновляется независимо от оригинала, пользователь может
  держать обе программы.
- Мерж апстрима остаётся дешёвым: код и структура решения не расходятся.
- Guard-тест на локализацию ловит строку со старым именем, пришедшую из апстрима.

### Negative

- В коде и в интерфейсе разные имена: namespace `MarkMello.*` у приложения
  Softmark. Это осознанная цена дешёвых мержей.
- Каждый мерж апстрима, который трогает `.iss`, воркфлоу или таблицу ассетов,
  требует разрешить конфликт вручную.

## Out of Scope

- перенос настроек из каталога `MarkMello`;
- подпись и нотаризация сборок;
- переименование репозитория на GitHub (делается в настройках репозитория).
  Оно должно случиться **до первого релиза**: ссылка на GitHub в интерфейсе и
  источник релизов локальной сборки уже указывают на `kostyatab/Softmark`, а CI
  берёт имя репозитория из `GITHUB_REPOSITORY` — релиз из ещё не
  переименованного `kostyatab/MarkMello` искал бы обновления там;
- выпуск первого релиза.
