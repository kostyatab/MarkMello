## Как устроен Preview Handler

- In-proc COM-сервер (DLL), который Проводник загружает в суррогатный процесс
  `prevhost.exe` (изоляция по умолчанию). Обработчик реализует
  `IPreviewHandler`, `IObjectWithSite`, `IOleWindow`, один из
  `IInitializeWith*` и, желательно, `IPreviewHandlerVisuals` (цвет фона и
  шрифт от Проводника — светлая/тёмная тема).
- Регистрация per-user, без прав администратора (HKCU; установщик MarkMello
  пишет в `HKA`, то есть в HKCU при установке для одного пользователя):
  - `Software\Classes\CLSID\{clsid}` — имя, `AppID =
    {6d2b5079-2f0b-48dd-ab7f-97cec514d30b}` (64-битный `prevhost.exe`),
    `InprocServer32` = путь к DLL, `ThreadingModel = Apartment`;
  - `Software\Microsoft\Windows\CurrentVersion\PreviewHandlers` — значение
    `{clsid}` с именем обработчика;
  - привязка к типу: `Software\Classes\<ключ>\shellex\{8895b1c6-b41f-4c1c-a562-0d564250836f}`
    = `{clsid}`, где `<ключ>` — расширение `.md` или ProgID (см. ниже).
- Содержимое показывается в дочернем окне, которое обработчик создаёт внутри
  `HWND`, переданного в `SetWindow`. HTML — через WebView2 (Evergreen Runtime
  есть в Win11 и в обновлённой Win10).

## Технология: C# NativeAOT COM или C++-обёртка

| | C# NativeAOT (`ComWrappers`) | C++-обёртка над NativeAOT-библиотекой |
|---|---|---|
| COM-сервер | `[GeneratedComClass]`/`[GeneratedComInterface]` (.NET 8+) и экспорт `DllGetClassObject`/`DllCanUnloadNow` через `UnmanagedCallersOnly` | обычный ATL/WRL-класс, как у образцов Microsoft |
| WebView2 | официальная .NET-обёртка `Microsoft.Web.WebView2.Core` использует встроенный COM interop — **не совместима с NativeAOT**; интерфейсы `ICoreWebView2*` пришлось бы описывать вручную | официальный C++ SDK, `WebView2LoaderStatic.lib` |
| Рендер Markdown | прямо в той же DLL | вызов `mm_render_html` из NativeAOT-библиотеки — **тот же C-интерфейс, что у расширения macOS** |
| Сборка в CI | только .NET | + MSVC (есть на `windows-latest`) |
| Выгрузка DLL | NativeAOT-библиотеку выгрузить нельзя (`DllCanUnloadNow` всегда `S_FALSE`) | обёртку — можно, NativeAOT-часть — нет |

**Предварительный выбор — C++-обёртка.** Главный довод — WebView2: без
AOT-совместимой .NET-обёртки C#-путь превращается в ручное описание десятков
COM-интерфейсов. Второй довод — один C-интерфейс рендера (`mm_render_html` /
`mm_free`) на обеих платформах: Swift-обёртка на macOS, C++-обёртка на Windows,
рендер один. Подтвердить на spike: собрать минимальную обёртку и замерить
время до первого показа.

## Способ инициализации

- `IInitializeWithStream` — рекомендация Microsoft: обработчик получает только
  поток, работает и для файлов внутри zip, безопаснее. Но пути к файлу нет —
  **относительные картинки не разрешить**.
- `IInitializeWithFile` — путь к файлу, относительные картинки работают;
  файлы внутри zip превью не получат.

**Предварительный выбор — `IInitializeWithFile`**, как у обработчика Markdown в
PowerToys: превью `.md` без картинок из соседних файлов заметно хуже, а `.md`
внутри zip — редкий случай. Проверить на spike: какой интерфейс
`prevhost.exe` запрашивает первым, если реализованы оба, и работает ли
`IInitializeWithFile` при включённой изоляции.

## Соседство с чужим обработчиком `.md`

Для одного типа Проводник берёт один обработчик. PowerToys (File Explorer
add-ons → Markdown) пишет `{clsid}` в
`HKCU\Software\Classes\.md\shellex\{8895b1c6-…}` — ровно тот ключ, который
занял бы и MarkMello. Перетирать его нельзя.

Варианты:

1. **Регистрироваться на ProgID `MarkMello.Markdown`**, а не на `.md`.
   Превью MarkMello действует, когда MarkMello выбран приложением по умолчанию
   для `.md` (через `UserChoice`); чужая регистрация на `.md` не трогается.
   Проверить на spike: порядок поиска shell-расширений — ProgID из
   `UserChoice` раньше ключа расширения или позже. Если позже — PowerToys
   на `.md` всё равно выиграет, и это нормально.
2. Регистрироваться на `.md`, **только если ключ пуст**; при удалении — убирать
   значение, только если оно всё ещё наше. Установщик показывает флажок
   «Предпросмотр Markdown в Проводнике», неактивный, если ключ занят чужим
   обработчиком.

Рекомендация — вариант 1, если spike подтвердит порядок поиска, иначе
вариант 2. В обоих случаях чужой обработчик не перетирается, а выбор
«по умолчанию» остаётся за пользователем (ADR-0004: «registered and
available», не «forcibly default»).

## Что учесть в реализации (известно заранее)

- Папка данных WebView2: по умолчанию — рядом с исполняемым файлом, то есть в
  `System32` для `prevhost.exe`, куда писать нельзя. Нужна своя, например
  `%LOCALAPPDATA%\MarkMello\PreviewWebView2`.
- Без сети: HTML с картинками в `data:` URI, навигация наружу запрещается в
  `NavigationStarting`, плюс CSP в документе.
- Тема: цвет фона от `IPreviewHandlerVisuals::SetBackgroundColor` и системной
  темы, не из настроек MarkMello.
- Первый показ: WebView2 создаётся асинхронно (сотни мс на холодном старте) —
  замерить на spike.
